# synbio-bench

A model-agnostic agent harness for measuring how well different AI models perform at synthetic-biology
design tasks. The first task family is **DNA origami**: agents design structures in
[scadnano](https://scadnano.org) (Python library), and the designs are tested with
[oxDNA](https://github.com/lorenzo-rovigatti/oxDNA) coarse-grained simulations.

The agent is built on [LangChain Deep Agents](https://docs.langchain.com/oss/python/deepagents/overview).
Every model gets the identical harness (system prompt, tools, skills, budgets). Only the chat model changes.

## Experiment design

**Independent variable:** the model (`configs/models.yaml`, any LangChain `provider:model` string).

**Tasks** (`tasks/origami/*.yaml`) are ordered by difficulty. Each has a natural-language brief and a
machine-checkable spec:

| task | lattice | helices | bp/helix | scaffold | what it tests |
|---|---|---|---|---|---|
| `4hb-square` | square | 4 (2×2) | 60–72 | 240–290 nt | basic API use, routing, stapling |
| `rect-sheet-8x96` | square | 8, planar | 90–100 | 720–800 nt | 2D sheet, alternating crossovers, twist |
| `6hb-honeycomb` | honeycomb | 6, ring | 115–135 | 700–820 nt | 3D bundle, closed ring, 21-bp period |
| `12hb-honeycomb` | honeycomb | 12, compact | 78–90 | 940–1080 nt | multi-neighbour 3D routing |

Each scaffold is a contiguous M13mp18 fragment, so structures stay small enough to simulate quickly.

**Flat shapes at different sizes** (`tasks/origami-shapes/`, generated by `scripts/make_shape_tasks.py`):
rectangle (3:2), equilateral triangle, disk and five-pointed star, each at scaffold sizes of 500, 1000,
2000, 4000 and ~7000 nt (stars from 2000 nt up). That gives a scaling curve per model.

**Literature designs** (`tasks/origami-rothemund/`): Rothemund's 2006 rectangle (24 × 288 bp) and tall
rectangle (32 × 224 bp) at full M13 scale. The original cadnano files (`reference_designs/cadnano/`, see
`SOURCES.md`) import into scadnano and serve as reference designs.

Shape tasks add a **shape score**: the IoU between an outline and the ideal shape of the same area, at the
best rotation and position (`src/synbio_bench/origami/shapes.py`). Two outlines are scored:
- the design footprint (0.34 nm per bp × 2.6 nm per helix), which the agent sees during validation;
- the relaxed oxDNA mean structure, projected onto its plane. This one goes into the grade.

Wrong shapes score ~0.65–0.70, so treat IoU above ~0.9 as a good match. Shape tasks weight
spec / base pairs formed / simulated shape equally.

**Agent loop.** The agent reads skills, writes scadnano scripts, runs them, validates, simulates and iterates,
then submits. Its tools:

| tool | purpose |
|---|---|
| `read_file`, `write_file`, `edit_file`, `ls`, `glob`, `grep` | deep-agents filesystem, sandboxed to the run workspace (`/`) and read-only `/skills/` |
| `run_python` | execute a design script in the workspace |
| `validate_design_file` | legality, sequences, crossover adjacency, task spec checks, design summary |
| `find_crossover_offsets` | geometrically valid crossover offsets between two helices of a draft design |
| `simulate_design` | oxDNA "quick" protocol: base-pair occupancy, RMSF, RMSD, long-bond report (budgeted, default 4) |
| `submit_design` | record the final answer |
| `write_todos`, `task` | deep-agents planning and subagents |

**Skills** (`skills/*/SKILL.md`) load progressively: the agent sees each skill's name and description
and reads the full text on demand.
- `scadnano-python`: API patterns and a worked example
- `origami-design-rules`: lattice geometry, crossover spacing, staple rules, failure modes
- `oxdna-testing`: how to read simulation output

**Grading** happens independently of the agent's own simulations. The grader re-runs a longer "standard"
oxDNA protocol on the submitted design with fixed seeds:

- `valid`: loads, legal, has a scaffold, every base sequenced, no mismatched designed pairs
- `spec_score`: mean pass fraction over spec checks (lattice, helix count, bp per helix, scaffold length,
  M13 source, coverage, staple lengths, compactness or planarity, connectivity, crossover adjacency)
- `sim_score`: mean fraction of designed base pairs hydrogen-bonded in the second half of production MD
- `overall = 0.5·spec + 0.5·sim` (0 if invalid). Weights are set in `configs/experiment.yaml`.
  Raw metrics (RMSF, RMSD to design, extents, initial stretched bonds) are kept for other analyses.

**Process metrics:** tokens (input/output/cache), optional cost, wall time, model calls, tool-call counts,
simulations used, and termination reason (completed / recursion_limit / wall_timeout / error).
Full transcripts are saved for qualitative analysis.

**Controls**
- `synbio-bench baseline` grades the expert reference design (`reference_designs/`) as a positive control.
  It also confirms that the grader and simulator rate a known-good design highly.
- Use `repeats ≥ 3` per (task, model) and report mean ± sd. LLM runs are stochastic.
- oxDNA conditions are fixed: oxDNA2, 1 M NaCl, 25 °C, average-sequence model.

## Setup

```bash
uv sync
cp .env.example .env    # add API keys
```

### oxDNA (Windows → WSL)

oxDNA has no native Windows build. Install a WSL distro once from an **admin** PowerShell (this may need a reboot):

```bash
wsl --install -d Ubuntu
```

Then build oxDNA with CUDA inside it:

```bash
wsl -d Ubuntu -- bash /mnt/c/synbio-ai/scripts/setup_oxdna_wsl.sh
```

`configs/oxdna.yaml` defaults to `mode: wsl`, `executable: /usr/local/bin/oxDNA`, `backend: CUDA`.
On Linux/macOS, use `mode: local`. To exercise the harness without a simulator, set `OXDNA_MODE=mock`.
Mock metrics are synthetic and flagged in every result.

## Running

```bash
uv run synbio-bench baseline                                    # positive control
uv run synbio-bench run --model claude-sonnet-5-5 --task origami/4hb-square --repeats 1   # one pilot run
uv run synbio-bench run                                         # full grid from configs/experiment.yaml
uv run synbio-bench run --no-eval --parallel 4                  # agents only, then:
uv run synbio-bench evaluate                                    # grade later (GPU-bound, serialized)
uv run synbio-bench report                                      # runs/<name>/results.csv + summary.md
uv run synbio-bench --experiment configs/shapes.yaml run        # flat-shape scaling study
uv run synbio-bench evaluate --reanalyze                        # recompute metrics without re-simulating
```

Runs resume: a run directory that already has `result.json` is skipped.

### Figures and reports

Every graded run gets figures in `figures/`, rendered locally from the design and the grader's simulation
(`src/synbio_bench/origami/viz.py`):
- `design.svg`: a scadnano-style path view. The scaffold is thick blue and staples are coloured; 5' ends are
  squares and 3' ends arrows. Designed base pairs that failed to form in simulation are shaded red.
- `structure_occupancy.png`: the oxDNA mean structure from three orthogonal directions, coloured by how
  often each base pair is formed. Shape tasks overlay the fitted target outline.
- `structure_strands.png`: the same views coloured by strand.

`report` also writes `runs/<name>/report.html`, with the summary table and one card per run (figures,
metrics, errors, rationale, links). `report --embed` writes `report_embedded.html`, which has the images
inlined so it can be shared as a single file. To inspect a structure interactively, drag the linked
`initial.top` and `last_conf.dat` into [oxView](https://sulcgroup.github.io/oxdna-viewer/).

Output per run: `runs/<experiment>/<task>/<model>/rep<k>/` contains `workspace/` (the agent's files, its
simulations, `final/design.sc`), `transcript.json`, `agent.json` and `result.json`.

## Tests

```bash
uv run pytest
```

The smoke tests need neither API keys nor oxDNA. They use a scripted model and the mock simulator.

## Caveats

- `run_python` executes model-written code on the host, with the workspace as its working directory.
  For untrusted models, run the harness inside a container or VM.
- scadnano exports helices 3 nm apart (real packing is ~2.5 nm). RMSD-to-design includes that offset, so
  compare RMSD across models, not against zero.
- The quick and standard protocols are short by origami standards. Before drawing conclusions, check that
  `sim_score` is stable across seeds on the reference design and a few submissions.
- Flat sheets twist in solution. On the quick protocol, Rothemund's rectangle (10.67 bp/turn) twists ~57°
  end to end and its simulated shape IoU is 0.88 (99.3% of base pairs formed). With one deletion per helix
  every 48 bp (`rothemund.py rect-twistfix`) the twist drops to ~33° and the IoU rises to 0.90. The shape
  score therefore rewards twist correction, and ~0.9 is about the best a flat full-size sheet reaches.
- Grading cost: a full-M13 design (~14k nt) takes ~13 min on the quick protocol and ~95 min on the standard
  protocol on a GTX 1660. Small designs (<2k nt) take ~5 and ~35 min.
- Adding a task family: add a `tasks/<family>/` spec, tools under `src/synbio_bench/<family>/`, and skills.
